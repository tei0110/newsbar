# newsbar 初版 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **担当の区別（必ず守る）:** 各タスクの見出しに **[Claude]** か **[ユーザー]** が付いている。**[ユーザー]** のタスクは、ユーザー本人がRustの勉強として書く。実行役（エージェント）はそこで止まり、ユーザーから「できた」と言われたらレビューだけを行う。ユーザーが「この段階は引き取って」と明示しない限り、[ユーザー]タスクの関数本体を書いてはいけない。

**Goal:** RSS/Atomの新着を集めてAIで日本語要約し、Macのメニューバーから読めるアプリ `newsbar` の初版を作る。

**Architecture:** Cargoワークスペースに、Tauriに依存しない `newsbar-core`（取得・解析・保存・新着判定・要約・本文抽出・更新処理）と、Tauri v2 アプリ `src-tauri`（メニューバー・小窓・設定画面・スケジューラ・キーチェーン）を置く。画面は Vite + 素のTypeScriptで、Rustのコマンドを呼んで結果を表示するだけにする。

**Tech Stack:** Rust 1.99（edition 2024）、Tauri 2.12、feed-rs、reqwest、rusqlite（SQLite）、html2text、dom_smoothie、keyring、smappservice-rs、Anthropic Messages API（raw HTTP）、Vite + TypeScript

**Spec:** `docs/superpowers/specs/2026-10-26-newsbar-design.md`（実行役は計画と設計書の両方を読むこと）

## Global Constraints

- 対象: macOS（arm64）のみ。バンドルIDは `io.github.tei0110.newsbar`、アプリ名は仮に `newsbar`
- Rust edition 2024、ワークスペースの `resolver = "3"`。開発機の rustc は 1.99.1
- 依存バージョン（この版で固定する）: `tauri = "2.12.5"`、`tauri-build = "2.7.4"`、`tauri-plugin-positioner = "2.4.0"`（feature `tray-icon`）、`tauri-plugin-opener = "2.7.2"`、`@tauri-apps/cli` と `@tauri-apps/api` は `2.12.4`、`feed-rs = "3.0.0"`、`reqwest = "0.13.5"`（feature `json`）、`rusqlite = "0.41.0"`（features `bundled`, `chrono`）、`tokio = "1.54.1"`、`chrono = "0.4.45"`（feature `serde`）、`serde = "1"`、`serde_json = "1"`、`thiserror = "2.0.21"`、`url = "2.5.8"`、`html2text = "0.17.4"`、`dom_smoothie = "0.18.2"`、`async-trait = "0.1.92"`、`keyring = "4.2.0"`、`smappservice-rs = "0.1.3"`、テスト用に `wiremock = "0.6.5"`、`tempfile = "3.27.0"`。Tauri 3 はアルファ版なので使わない
- 依存ライブラリのライセンスは MIT / Apache-2.0 / BSD / ISC / Zlib に限る。GPL系は入れない（設計書5章）

- APIキーはキーチェーンにだけ保存する（service `io.github.tei0110.newsbar`、account `anthropic_api_key`）。SQLite・ログ・リポジトリには絶対に書かない
- Anthropic API: `POST https://api.anthropic.com/v1/messages`、ヘッダー `x-api-key` と `anthropic-version: 2026-10-21`。既定モデルは `claude-haiku-5-5`（設計書8.3「Haikuクラス」）。`output_config: {"effort": "low", "format": {"type": "json_schema", ...}}` を使う

- 画面の文言は日本語で、各タスクに書いた文言をそのまま使う
- テスト用のフィードやHTMLは、実在サイトの構造をまねた合成サンプルにする。実際の記事本文はリポジトリに入れない（公開時の著作権への配慮。設計書10章の「実サイトのサンプル」から変更した）
- Claudeが作るコミットの末尾には `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` を付ける。コミット用のメールアドレスは、リポジトリに設定済みのnoreplyアドレスを使う

## Review Focus

1. **相対URLのリンク**: Atomなどで `<link href="/2026/oct/25/post/">` のような相対URLが来たら、フィードのURLを基準に絶対URLへ直す → Task 2 `atom_relative_link_is_resolved`
2. **UTF-8以外の文字コード**: 日本のサイトにはShift_JISのフィードがある。文字化けせずにタイトルが読めること → Task 2 `shift_jis_feed_is_decoded`
3. **巨大なレスポンス**: 数十MBのフィードやページが返ってきても、メモリを使い果たさずにエラーとして扱う → Task 2 `fetch_rejects_oversized_feed`、Task 15 `fetch_rejects_oversized_page`
4. **フィードではないURLを追加しようとした**: 普通のWebページのURLを情報源に追加しようとしたら、わかりやすい理由で断る → Task 9 `validate_rejects_html_page`
5. **オフラインやスリープ明け**: すべての取得が失敗しても落ちず、既存の記事は残り、エラーが状態に出る → Task 9 `offline_refresh_keeps_existing_articles`

CREATE TABLE IF NOT EXISTS sources (id INTEGER PRIMARY KEY, name TEXT NOT NULL,

  last_fetched_at TEXT, last_error TEXT);
CREATE TABLE IF NOT EXISTS articles (id INTEGER PRIMARY KEY,
  source_id INTEGER NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
